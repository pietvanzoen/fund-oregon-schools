# 2026-11-21

## Source facts, derived figures and analysis kept apart (issue #34, part 1)
- Topic files now have three fixed sections, in order: "What the sources say" (every line cited, no inference),
  "Derived figures" (our sums, shares and estimates, each tagged `[DER:<topic>/<id>]`) and "Analysis". The inline
  "Analysis:" label isn't needed there; the heading does that job.
- Every calculated value goes in `analysis/derived/<topic>.csv`, written only by a plain `tools/derive_<topic>.py`
  (`id, value, unit, kind, label, method, inputs, assumptions`; `kind` is `derived` or `est`). `analysis/data/`
  keeps only values copied from sources.
- `tools/check_citations.py` checks the sections, that every `[DER:...]` resolves and matches the number shown
  next to it, and that a DER figure in BRIEFING sits in a sentence marked "our sum" or "our estimate". It warns
  when a number under "What the sources say" isn't in the text of a source the line cites. CI reruns every derive
  script and fails if `analysis/derived/` changes.
- `topics/reserves.md` converted. It has no calculated figures (every number is stated in a cited source), so
  there's no `derive_reserves.py`; `data/reserves.csv` is unchanged.
- BRIEFING: the "about $1.2B" and "$3.65B" sentence was labelled Analysis but both figures are printed in the 2026
  QEM report, so it's now a cited source statement. Three inline "Analysis:" passages moved to their own list
  items. No figures changed.
- Website: every `analysis/topics/*.md` is published automatically under Topics, titled by its H1. DER tags show
  as "🧮 our sum" or "🧮 our estimate", linked to the derived CSV.
- `CLAUDE.md` rules 2, 4, 8, 9 and 10, both skills, the volunteers' skill and both reviewer prompts updated
  (reviewers now report "wrong section" findings). New source folders from #32 documented: `legislature/lpro/`,
  `ode/ssf/`, `ode/charter/`, `ode/legislation/`. Plugin version 0.2.0.

## Finding documents (`fos-work-issue` 0.2.1)
- Lessons from #20, where two guessed URLs 404'd and the browser found the live link: take URLs from a link on the
  agency's page, never from a file-name pattern; look with web search and fetch first, then the built-in browser if
  the session has it, else list the document as "needs a browser" (never wait on it unattended); check a URL before
  queueing; on a 404, go back to the source page instead of guessing; don't cite facts seen only in the browser.
- Queue rows end `notes` with `from: <page URL>` so a dead link can be re-found (also in `RUNBOOK.md`).
