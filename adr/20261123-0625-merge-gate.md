# A run merges its own PR only through a written gate, and the gate starts in shadow mode

Status: accepted (2026-11-23, PR #TBD)

## Context
Every nightly PR waits for Piet, so the archive moves only as fast as he reads. Most research PRs are checked
three times before he sees them (fact-check, consistency-fairness, clarity) plus CI. But nobody has measured how
many errors those reviewers catch: no seeded test yet, one `escaped-error` issue (#114), no `false-alarm` labels.
Merging on their word before that is a guess.

## Decision
`fos-work-issue` step 8 holds a written merge gate. A run checks it on every PR and records the result in the PR
("Merge gate: would merge" or "wouldn't merge: rule N"). The run merges only when the gate passes **and** the
Research queue issue carries the `auto-merge` label. Piet adds that label; runs only ever remove it. Until then
the gate runs in shadow mode: the result is recorded, and Piet merges. The gate excludes tooling and rule changes,
headline pages, on-the-record content (quotes, positions, promises), corrections, and any PR whose review left a
finding open.

## Options weighed
- **Keep Piet merging everything**: safest; the archive stalls whenever he's busy, and the three-PR cap stops
  the nightly runs.
- **Auto-merge whatever the reviewers pass, now**: fastest; trusts reviewers that have never been scored.
- **Gate in shadow mode, switched on after the reviewers are scored** (chosen): costs a few weeks of Piet
  merging, but every PR in that time tests the gate too. A "would merge" PR in which Piet finds an error is a
  gate miss.
- **Switch in a file or a repo variable**: switching off would then need a PR, or settings access the sessions
  don't have. A label on the queue issue can be removed from a phone and read by any run.
- **GitHub's own auto-merge**: turned off for this repo, and it checks only CI, not the review outcome.

## Revisit when
The test set and Piet's labels show the reviewers' scores, which decides whether to add `auto-merge`. Look
again after any `escaped-error` in an auto-merged PR, and if most PRs fail the gate on rule 3 (quotes and
positions), which would mean the gate is too narrow to matter.
