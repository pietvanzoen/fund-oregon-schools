# Code is linted and the built HTML validated in CI, with pinned tools; no browser checks yet

Status: accepted (2026-11-24, PR #175)

## Context
The site build caught broken links, unknown `[[id]]`s and missing meta descriptions, and Vale covered prose, but
nothing checked the JS in `site-11ty/`, the Python in `tools/`, the workflows, or the markup and accessibility of
the built pages. CLAUDE.md lists site accessibility under "never cut". Most code here is written by agents across
many sessions, so style drifts without a formatter.

## Decision
Four checks, each pinned and run only in GitHub Actions, each failing the PR:
- **html-validate** (`html-validate:recommended`, `site-11ty/.htmlvalidate.mjs`) on `_site/` after the build in
  `pages.yml`: invalid HTML plus the accessibility rules visible in markup (alt text, names on controls, heading
  order, ARIA).
- **Biome** (`site-11ty/biome.json`) lints and formats `site-11ty/src` and `eleventy.config.js`, in `pages.yml`.
- **Ruff** (`ruff.toml`) lints and checks formatting of `tools/`, in `lint.yml`.
- **actionlint** checks `.github/workflows/`, in `lint.yml`.

Sessions may run them locally (`npx biome check --write`, `pip install ruff`), but nothing in `tools/` needs them:
the stdlib-only rule (`20261122-1551-vale-in-ci-stdlib-in-tools.md`) stands.

## Options weighed
- **html-validate** (chosen): no browser, a second or two of CI. Misses anything that needs rendered CSS, such as
  colour contrast and focus visibility.
- **pa11y-ci with the axe runner**: catches contrast and other rendered problems, but needs headless Chrome in CI.
  Not adopted for now.
- **Playwright with axe**: can open the glossary preview cards and search before scanning, but is site test code,
  which CLAUDE.md rules out.
- **Lighthouse CI**: a subset of axe plus performance scores that vary between runs. Not adopted.
- **Biome** (chosen) vs **ESLint and Prettier**: one pinned package instead of about a hundred, lint and format in
  one pass. Biome has fewer rules and plugins; none are needed here.
- **Formatting `analysis/` Markdown**: not adopted. A formatter would rewrap prose and the `key: >` front matter
  the site's own parser reads.
- **A test framework for site code** (`node:test`): not adopted; the build still covers the site
  (`20261121-1526-no-test-framework-for-now.md`).
- **External link checking**: not adopted. Agency URLs rot often, and the archive keeps copies for that reason.

## Revisit when
A contrast or focus problem reaches the site, or the site gains more interactive parts: then add pa11y-ci with the
axe runner on one page per template. Reopen Biome if a needed rule exists only as an ESLint plugin.
